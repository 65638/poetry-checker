# 六人五天项目总结

项目：诗格律检查器

周期：2026-10-16 至 2026-10-22（按五天主开发周期整理，后续为收口与修复）

当前主线：`main@d5e9f27`

## 一、项目目标

项目从一个格律判定底座，发展为包含校诗台、藏韵阁和典籍馆的可用网页工具。核心目标是：输入诗文后进行形制、平仄、押韵、粘对等检查；给出可追溯的候选读音和来源；允许用户查字、改稿、荐字、对读和保存推敲过程；在资料或模型不完整时仍然让网页可用，并明确说明参考性质。

## 二、六个主角色与职责

项目任务书的六个主角色为“组长/GLM + A–E”。Codex 作为跨模块契约、格律核心和后续收口协作者单列，不把它混入六个主角色的工作量统计。

| 角色 | 主要职责 | 交付结果 |
| --- | --- | --- |
| 组长/GLM | 根配置、API、集成、运行协调 | Fastify 服务、真实编排、模型配置、CI 和主线合并 |
| A | 三套韵书、原始来源、候选和审核记录 | 平水韵、词林正韵、中华新韵快照及来源清单；16 项用户明确接受的词林候选 |
| B | 原文解析、字位、语境读音和版本证据 | 逐字位置绑定、全库语境资料、正文版本和竞争读音保留 |
| C | 格律核心、规则卡、独立复核 | 形制、模板、平仄、粘对、韵部、异常解释和独立规则验收 |

## 四、当前已交付能力

### 校诗台

- 输入诗文、选择韵书和体式提示，返回形制、模板、押韵、平仄及条件性诊断。
- 自动处理多候选读音；模型只能从当前韵书候选中选择。
- 用户手动选音优先于模型；选音、改稿和迟到响应有输入身份守卫。
- 分析失败、超时或模型不可用时，保留本地分析和原文，不展示混合的新旧报告。
- 可复制摘要、导出报告，并保留来源、数据版本、规则版本和模型标识。

### 藏韵阁

- 三书查字、候选、韵部、现代读音、反切和证据展开。
- 独立广韵参考与原字/关联字形区分。
- 诗句停笔后自动辨音；悬停批注 800ms 后定位，点击/键盘立即定位。

### 典籍馆

- 读取和导入 JSON/JSONL 诗库，保留正文、版本、来源、作者和标签。
- 题名、作者、原句、选集、文类、朝代筛选，原诗阅读和逐字注音。
- 诗境检索可返回原诗引句并回到作品。
- 对读支持两首诗并排或窄屏上下阅读，比较意象、情绪、结构、节奏和对仗。
- 同韵寻字按真实韵部分页，结合全诗筛选候选。
- 推敲笺保存版本、时间、修改原因，支持导入/导出、撤销和恢复。

## 五、数据与模型边界

- 三书当前是“参考分析”口径，未审核数据不阻断网页，但不能宣称全库人工审核完成。
- 原始来源、来源 SHA、旧运行 SHA 和人工接受记录保留可追溯性。
- 2022 篇作品目录及逐字资料已接入；来源主要来自聚合站，读音仍需持续独立核验。
- DeepSeek 和 GLM 都是辅助辨音/评议模型，不是古音权威。模型不能创建候选、伪造来源、把普通话声调直接映射为古音平仄，不能为了合律改读多音字。
- “五更”的“更”案例明确了后续口径：语境读音 `gēng` 可以与格律所需仄声发生真实冲突，应报告冲突，而不是偷偷改读 `gèng`。

截至 `d5e9f27`：

- `pnpm verify`：77 个测试文件、957 项测试通过；lint、类型检查、工作区构建和契约/模板生成物检查通过。
- 主线整合记录：真实 API 九格 9/9 通过，浏览器基础回归 19/19 通过。
- 典籍馆与推敲台、自动辨音、悬停定位、三分区导航、性能和离线运行均有独立回归记录。
- 性能基线：本地平水分析 600 个有效 HTTP 200、0 失败；并发 1 P95 约 19.0ms，并发 4 P95 约 26.9ms。该数值不包含外部模型耗时。
- 两个本地预览已重启，`/readyz` 为 ready，模型状态为 DeepSeek `deepseek-flash`。

## 七、仍需诚实标出的边界

1. 全库来源、古音事实、词林/新韵独立期望和模型语义质量不能由工程测试替代。
2. 诗境检索目前是候选作品范围内的相邻句/意象匹配与模型排序，不是全库向量检索。
3. 同韵推荐只覆盖当前分页提供的候选，不代表遍历整个韵部后得到最优文学用字。
4. 重复作品需要按正文、版本、来源和组诗关系继续治理，不能只按题名去重。
5. 受控模型回归证明契约和归属，不证明 DeepSeek/GLM 的长期准确率、余额或古音判断质量。
6. 外部模型超时、限流、权限失败仍可能发生；当前策略是有限等待、失败回退和可重试，不做自动无限重试。

## 八、后续建议顺序

1. 继续补齐“语境读音 vs 格律要求”的简评模板和可读改字建议，尤其覆盖多音字冲突。
2. 建立诗库版本/组诗去重与关联展示规则，优先处理“行路难”类重复。
3. 增加真实 DeepSeek 失败、迟到失败和多批次超时的浏览器回归，但不要把 Key 或用户原文写入证据。
4. 持续补来源独立核验和人工接受记录，再决定是否把任何数据从参考提升为权威。
