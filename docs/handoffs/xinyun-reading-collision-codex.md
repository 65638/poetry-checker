# 新韵同部多读音修复

2026-10-21，Codex 在 `codex/glm-reading-assistant`、基线 `e4f0245` 接管 `scripts/data/build-xinyun.ts`、新韵新快照及迁移记录、`apps/api/src/reading-assistant.ts` 和相关测试；展示层仅补充声调显示。A 的数据工作和 API 自动辨音已由用户授权 Codex 接管。本工作位由 Codex 单独写入，原共享目录不改写。修复和复验完成后按现有 PR #31 交集成方。

复现：新韵“空余”的原始来源 `U+4F59: yú,tú,xú,yù` 有四个读音，但旧生成器对同字、同声调、同韵部排序后只生成第一个读音的候选，导致十二齐阳平只留下 `xu2`。模型选中了该候选 ID，却在 pronunciation 和理由中写 `yú`；服务端又优先输出候选内的 `xu`，产生矛盾。

修复范围：为源数据中每个同部读音生成独立候选；旧候选 ID 和内容保持不变，新增读音带拼音与声调后缀。新快照单独版本化，旧快照和历史摘要记录保留。生成迁移表并检查旧候选完整保留，不修改 reviewStatus。模型明确拼音与候选不符时，该字位退回不确定，不把矛盾结果自动应用；其他字位继续使用。页面显示声调。

核验结果（`e4f0245` + 本轮未提交修改）：

- `pnpm verify` exit 0：64 文件、848 测试，lint、类型、构建和8项生成检查通过。
- 新快照 53,173 候选，旧快照 51,608；1,508 组同部多读音补回 1,565 条候选。逐项保留所有旧候选，并对全部可映射非轻声源读音做完整覆盖测试；43 条原来不可映射的源读音仍不可映射，241 条轻声仍排除。
- `pnpm test:acceptance` exit 0：真实本地资源九格 9/9、无阻断和执行错误，按既有 runner 禁用模型，结论包含 needs_review/fail/not_applicable，非九格格律全 pass。
- 真实预览 `http://127.0.0.1:56102/#checker` 使用本地服务端 Key、真实智谱 API，浏览器提交新韵“此地空余黄鹤楼。”约 3,811.7ms 返回，`selectionMethod=model`、`selectedReadingId=xinyun:余:yangping:十二齐·阳平:yu2`；模型理由为剩余义，读 yú。
