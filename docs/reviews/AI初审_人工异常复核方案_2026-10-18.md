# AI 初审 + 人工异常复核方案

日期：2026-10-18  
适用阶段：D2 数据与真实 API 联调  
适用范围：平水韵、词林正韵、中华新韵、三首金标准作品、语境规则、格律规则卡

## 1. 采用的审核口径

本项目采用两级审核：

1. **AI 初审**：完成全量结构检查、来源引用检查、重复构建检查、候选覆盖统计和异常清单生成；
2. **人工异常复核**：组长只复核 AI 标出的异常、所有多音字、三首金标准的关键字位，并对最终审核范围签字。

AI 初审结果不等于人工批准。没有人工确认的条目继续保持 `unverified`。

## 2. AI 初审必须完成的内容

### 2.1 三套韵书

- 检查平水韵 106 部、词林正韵 19 部/33 子卷、中华新韵 14 韵/56 子卷；
- 检查韵部名称、声类、空韵部、重复韵部和意外韵部；
- 检查候选 → 韵部 → 证据 → 来源引用是否闭合；
- 检查同一 `dataVersion` 重复构建结果是否一致；
- 统计每库候选数、证据数、缺字数、多归部字数和未审核数；
- 检查简繁/异体字是否被未经依据地合并；
- 检查中华新韵重建表的生成器版本、规则版本和 pinyin-data SHA。

### 2.2 三首金标准

AI 生成 96 行逐字审核表，每行至少包含：

```text
caseId, tokenId, line, column, character, context,
candidateIds, toneOptions, groupIds, evidenceIds,
sourceIds, sourceLocators, ambiguity, machineDecision,
machineReasons, dataVersion
```

AI 必须标出：

- 候选缺失；
- 候选同时包含平、仄；
- 入声字；
- 多归部字；
- 简繁/异体差异；
- 证据为空或状态为 `unverified`；
- 语境规则缺失或候选冲突；
- 与格律模板结论可能产生冲突的位置。

### 2.3 规则和语境

- 检查 10 张规则卡的 `ruleId`、版本号和 `evidenceIds`；
- 检查每个 `evidenceId` 是否能找到来源和定位；
- 检查上下文规则的短语、目标位置、候选 ID 和证据 ID；
- 不允许用“符合格律”自动生成读音选择。

## 3. 人工必须复核的异常

以下情况不能由 AI 自动批准，必须由组长确认：

1. 同一字同时有平、仄候选；
2. 候选涉及入声、古今音映射或多归部；
3. 简繁、异体、异文存在争议；
4. 来源之间的韵部、声类或读音冲突；
5. 中华新韵重建规则无法从固定版本复现；
6. 作品正文、作者、体裁或特殊拗律存在版本差异；
7. 格律判断与读音候选冲突；
8. AI 输出 `unknown`、`ambiguous`、`conflict` 或 `source_missing`；
9. 规则卡来源只有概括，没有可定位章节/页码；
10. AI 不能给出可复核的来源定位。

当前三首诗的优先人工清单为：

- 《登鹳雀楼》：“更”；
- 《静夜思》：“望”“思”“乡”；
- 《黄鹤楼》：“乘”“空”“不”“汉”“乡”；
- 三首诗的正文版本和体裁标签；
- 平水韵三讲补缺 9 字。

## 4. 人工复核记录格式

新增记录建议使用：

```text
docs/reviews/13_J03三首核心诗逐字人审_第二批.md
```

每条异常至少填写：

| 字段 | 要求 |
|---|---|
| `caseId` / `tokenId` | 能定位到具体作品和字位 |
| 原字与上下文 | 保留原文，不改写异文 |
| 候选 ID | 使用仓库中的完整候选 ID |
| 证据 ID | 必须能回到快照中的证据 |
| 来源定位 | 书名、版本、卷/部、页码或固定网页修订号 |
| 人工结论 | `approved`、`ambiguous`、`unverified` 或 `rejected` |
| 说明 | 写明采用或拒绝的理由 |
| 审核人/时间 | 填真实姓名或课程要求的实名标识和实际时间 |

没有来源定位时，人工结论必须保持 `unverified`，不得为了通过测试补写页码或网址。

## 5. 状态规则

| 状态 | 含义 | 能否进入发布包 |
|---|---|---|
| `machine_checked` | AI 结构和引用检查通过，未完成人工复核 | 不能 |
| `human_reviewed` | 人工已复核该异常/样本 | 视范围而定 |
| `approved` | 在明确范围内完成责任人审核并可追溯 | 可以 |
| `unverified` | 证据或审核尚未完成 | 不能 |
| `rejected` | 来源或映射被人工否定 | 不能 |

公共契约 v1 的快照 `reviewStatus` 只有 `approved` 和 `unverified`，因此 `machine_checked`、`human_reviewed` 等中间状态放在审核记录和报告中，不修改契约字段含义。

## 6. 发布与联调口径

### 6.1 课程项目优先口径

完成 AI 初审、异常人工复核、三首金标准和关键规则后，可以宣告：

> 三库完成自动全量结构校验；关键样本和异常已人工复核；三首金标准进入金标准联调状态。

此时未覆盖的候选仍保留 `unverified`，不得宣称三库每个候选都已人工核验。

### 6.2 严格发布口径

只有下列条件全部满足，才允许将快照放入 `data/releases/`：

- 三套快照的结构门槛通过；
- 快照 `reviewStatus` 为 `approved`；
- 候选、韵部、证据、来源引用闭合；
- 三首作品元数据和语境规则已审核；
- 10 张规则卡引用闭合；
- `pnpm verify` 通过；
- `/readyz` 和三首真实 `/analyze` 通过。

如果没有完成上述范围，API 必须保留 `DATA_NOT_READY` 或 `needs_review`，不要把未审核数据静默变成成功结论。

## 7. 执行顺序

1. A/GLM 生成三库 AI 初审报告和异常清单；
2. B 生成 96 字位逐字表并标记 10 个多音重点；
3. E 固定三首正文、作者、体裁和异文范围；
4. C 复核规则卡和救法证据引用；
5. 组长只处理异常项并填写第二批人审记录；
6. GLM 按人工结论更新证据、语境规则和作品元数据；
7. 运行 `pnpm verify`、`pnpm check:generated` 和真实 API 探针；
8. 将剩余未审核项写入交付报告，不隐藏、不补造。
