## 3. 基本句式与 16 套模板

| 型 | 五言 | 七言 |
|---|---|---|
| A | ZZPPZ | PPZZPPZ |
| B | PPZZP | ZZPPZZP |
| C | PPPZZ | ZZPPPZZ |
| D | ZZZPP | PPZZZPP |

下面给出八句序列；绝句取前四句。起式名称按相应五言/七言第二字确定，不能把五言名称直接复用到七言。

| 五言起式 | 七言对应起式 | 八句序列 |
|---|---|---|
| 仄起首句不入韵 | 平起首句不入韵 | A B C D A B C D |
| 仄起首句入韵 | 平起首句入韵 | D B C D A B C D |
| 平起首句不入韵 | 仄起首句不入韵 | C D A B C D A B |
| 平起首句入韵 | 仄起首句入韵 | B D A B C D A B |

偶数句为必押韵句；首句入韵型再加第一句。P0 近体模板使用相应平声韵脚。词林正韵不能据“同一部含平仄”而允许随意平仄通押。

### 普通可变位与额外约束

基础模板可以表达允许集合，但必须叠加规则约束。建议教学基线如下，`中` 为 P/Z 候选集合，具体变体口径由组长在 D1 核定：

| 型 | 五言位置集合 | 七言位置集合 |
|---|---|---|
| A | 中仄中平仄 | 中平中仄中平仄 |
| B | 中平中仄平 | 中仄中平中仄平 |
| C | 中平中仄仄 | 中仄中平中仄仄 |
| D | 中仄仄平平 | 中平中仄仄平平 |

- B 型放宽第一/第三位后必须检查窄义孤平和自救，不能无条件通过。
- C 型形成三仄尾时生成 warning，不一律硬判出律。
- A 型相应第三字为仄涉及传统小拗口径，规则卡注明所采用的允许/提示政策；不能只写“奇位不论”。
- 不在已审核范围的特殊格式不自动认可；保留常格偏离与需复核提示。

## 4. 候选模板与特征

整首诗匹配一个模板，不逐句选择最优句式拼起来。用户给 formHint 时只比较该体式；结构不符仍指出，不改成古体。

每个 TemplateCandidate 返回：句型序列、逐位允许集合、必韵句、可判关键位比例和四种特征。score 使用固定权重：0.65 toneFit、0.20 relationFit、0.10 rhymeFit、0.05 parallelismFit；缺项重新归一化，全部缺失为 null。P0 没有可靠对仗特征就返回 null，不用现代分词器随便造分。

特征分母只包含该特征可判位置，同时单独报告 evaluatedKeyRate；unknown 不能作为吻合。评分只是候选排序，不是最终通过，也不是置信概率。E 负责阈值与体裁决策。

并列或近似候选要保留。若 selectedTemplateId=null，返回候选与明确的待确认结论，不随意采用首项制造确定错误。可以只输出跨所有候选都成立的诊断；其余保留为参考，不能硬判。

## 5. 规则实现

### 5.1 三值与未知

某字有效平仄集合 D、允许集合 A：D 非空且完整已知、D⊆A 则该项 pass；D∩A 为空且完整已知则 fail；部分相交为 uncertain；存在未知有效候选则 uncertain。

多字规则仅枚举相关位置的候选组合，或使用等价集合计算；不得暴力枚举整首诗所有读音。若合理组合全部符合为 pass，全部违反为 fail，混合为 uncertain。达不到可判条件就明确待确认。

### 5.2 粘对

同联出句/对句关键节奏应相对，上联对句/下联出句应相粘；以第二字为主要判别点，结合五言二四、七言二四六和整句谱式判断。

必须先识别已认可变格，再处理其相应位置对关系检查的影响。不能认可特拗后又机械对同一位置报告失对。每条关系输出涉及的 tokenIds 与 findingIds，供前端连线。

### 5.3 押韵

按模板检查必韵句，韵脚用当前书的有效读音归属和声类。检查所有韵脚公共归部，而非只看相邻对。

反例：候选部集合 `{A,B}`、`{B,C}`、`{A,C}` 两两相交但全体为空，不能判通过。只有部分合理读音配置同韵时 uncertain；全部可行配置都同韵才可确定通过。

同一个字的韵部和声调必须来自同一个有效候选，不能拿候选甲的平声拼上候选乙的韵部。遇到未查明的韵脚，不能将其排除后只比较剩余字。

首句借邻韵单列策略；P0 没有审核邻韵表时不自动放行，提示可能涉及借韵及其限制。

### 5.4 孤平、尾式

- 采用窄义 B 型平收句口径：五言 `ZPZZP`，或七言对应后五字，在无相应救法时触发孤平。
- 不是简单数“整句只有一个平声”。
- 末三字全平：三平尾 error；末三字全仄：三仄尾 warning。
- 未知或平仄歧义使尾式结果依组合变化时 uncertain，不用单一默认读音下结论。

### 5.5 P0 常见变格

| 类型 | 最低支持的形式 | 条件 |
|---|---|---|
| 孤平自救 | B 型五言 `ZPPZP`；七言对应尾部 | 指出拗位与救位，不能把所有 B 型偏离都算已救 |
| 特拗 | C 型五言 `PPZPZ`；七言对应 `中仄平平仄平仄` | 匹配完整审核模式和其余约束 |
| 对句相救 | `ZZPZZ / PPPZP`，如野火烧不尽/春风吹又生 | 同联对应 A/B 型，明确出句第四字与对句第三字；七言扩展需核定对应位置及前缀 |

更宽的跨句救法必须增加正反例并经审核；最低支持模式以外不能无限泛化。三类均需 P0 验收，不得只写文案。

已救时保留原偏离证据，用 resolvedBy 指向 RuleCard ID，相关 finding IDs 互相关联；认可变格后的当前状态可为 pass/info。不要把原偏离继续作为未解决 error 送给汇总器。

### 5.6 对仗边界

P0 提示律诗颔联/颈联需要对仗，简单同位重复或词类信息只作辅助，不宣称完整语义判断。未实现项要明确，不能降低整体字音/格律可信度，也不能硬编对仗置信分数。

## 6. 输出与规则依据

封装附录两个公共纯函数，调用同输入输出签名的 Core 接口，输出 ProsodyReport。每条 Finding 须有规则 ID/版本、状态、等级、字位、expected/observed、说明、模板、证据和救法关联。封装可校验结构及装配引用，不得改写核心状态来消除失败。

规则卡包含适用范围、形式条件、例外、正反例、所采用学术口径。王力《诗词格律》等实际版本、章节/页码待核实；没有定位不要捏造。可以先提供清楚的工程规则表达，但发布引用必须真实。

去重相关诊断：同一字可以引发平仄与失对两个有意义结果，但 UI 应能通过 relatedFindingIds 说明同源问题，不重复堆砌“错误数量”。

### 2. 术语、索引和状态

- `P` 表示平，`Z` 表示仄；未知不是第三种实际声调。
- `line`、`column` 从 1 开始，按诗句和汉字计数；`startUtf16/endUtf16` 是原始字符串中的半开区间。
- `tokenId` 为 `l{line}c{column}`，例如 `l4c1`。标点不占格律字位。
- `inputHash` 为原始输入 UTF-8 文本的 SHA-256 小写十六进制值。人工选音仅对该原文有效。
- 简繁和异体对应只生成候选，不覆盖原文；不得把“发”无条件合并到“發”或“髮”。
- `resolved/ambiguous/unknown` 分别表示读音确定、有多个合理候选、没有可用候选。
- 规则状态为 `pass/fail/uncertain/not_applicable/unsupported`。
- `not_applicable` 表示规则不适用；`unsupported` 表示形式或规则尚未实现；不得混用。
- `error/warning/info` 是问题等级，与规则状态独立。三仄尾默认 warning；其出现不自动使全篇 fail。
- 判定为 pass 不等于文学评价优秀，也不保证未实现的规则通过。

补充约定：

1. `expectedTones[句序号-1][字序号-1]` 是允许平仄数组；它只是基础模板，不能替代孤平、尾式、变格约束。
2. `possibleTones` 由有效候选计算。任一有效候选声调未知时，`toneStatus` 为 unknown，不能用其他已知候选掩盖它；所有有效候选同为平或同为仄时，平仄可确定而读音仍可 ambiguous。
3. `ze_unspecified` 用于来源只提供“仄声”、不能进一步区分上去的记录，不补造细分类。
4. `neutral` 没有可靠本调时 `tone=null`；不得默认归平。
5. `ContextRule.targetOffset` 按短语 Unicode 码点从 0 计数；每条规则所有短语的目标偏移必须一致，否则拆成多条。
6. 上下文规则若同时选中多个相互冲突候选，不自动任选；退回 ambiguous 并记录冲突。
7. 来源和规则 ID 是稳定标识；报告中引用的每个 ID 必须能在 provenance 或相应查询接口中解析。
8. unverified 的证据只能出现在待核查材料中，不得支撑确定的发布结论。
9. 作品指纹按去除约定的标点与空白后、保留原字形和字序的正文计算 SHA-256。简繁及异文各自登记审核指纹，不自动互认。该指纹不同于原文 inputHash。

### 4. 模块接口

```ts
// M1 / A：异步 I/O 适配器
lookupCharacters(input: {
  characters: string[]; rhymeBook: BookId; dataVersion: string;
}): Promise<LookupResult>

// M2 / B：纯计算。规则和证据由 API 装载后注入。
parseText(input: { text: string }): ParsedPoem
resolveReadings(input: {
  poem: ParsedPoem;
  lookup: LookupResult;
  overrides: ReadingOverride[];
  contextRules: ContextRule[];
}): AnnotatedPoem

// M3 / C：先产出特征，供体裁模块消费；不要导入 M5。
matchTemplates(input: {
  poem: AnnotatedPoem; formHint: 'auto' | FormId; ruleSet: 'teaching-v1';
}): TemplateCandidate[]

evaluateProsody(input: {
  poem: AnnotatedPoem;
  candidates: TemplateCandidate[];
  selectedTemplateId: string | null;
  applicability: GenreDecision['applicability'];
  ruleSet: 'teaching-v1';
}): ProsodyReport

// M5 / E：不用标题独立认定作品，也不修改读音。
classifyGenre(input: {
  poem: AnnotatedPoem;
  candidates: TemplateCandidate[];
  metadata: WorkMetadata[];
  genreHint: AnalyzeRequest['genreHint'];
  formHint: AnalyzeRequest['formHint'];
}): GenreDecision
```

API 由组长依次调用：请求校验 → parseText → M1 查询 → resolveReadings → matchTemplates → classifyGenre → evaluateProsody → 证据汇总 → 汇总结论。

不得形成 `prosody → genre → prosody` 的运行时依赖。两个步骤都由 API 调度。

分析请求示例：

```json
{
  "text": "白日依山尽，黄河入海流。\n欲穷千里目，更上一层楼。",
  "rhymeBook": "pingshui",
  "genreHint": "auto",
  "formHint": "auto",
  "ruleSet": "teaching-v1",
  "readingOverrides": []
}
```

人工覆盖是在上一次响应的原文、候选和 inputHash 基础上，将 `readingOverrides` 填为 `[{"tokenId":"l4c1","readingId":"实际候选ID"}]`。不能凭空提供读音。

规则输出片段（ID 为结构示意，发布时必须引用真实规则及证据）：

```json
{
  "id": "finding-l1c2-meter",
  "ruleId": "METER.POSITION",
  "ruleVersion": "1",
  "status": "fail",
  "severity": "error",
  "locations": [{"tokenId":"l1c2","line":1,"column":2}],
  "expected": ["Z"],
  "observed": ["P"],
  "message": "按所选模板，第一句第二字应仄，此处为平",
  "templateId": "实际模板ID",
  "evidenceIds": ["实际平声归属证据ID"],
  "resolvedBy": null,
  "relatedFindingIds": []
}
```

约束与错误：

- 请求不超过 2,000 个 Unicode 码点、100 个诗句；限额在后端执行。
- 没有汉字、枚举非法、指定 ancient 同时强选近体 form、覆盖读音无效：422。
- 有覆盖时 inputHash 必填并与当前原文一致；冲突为 422 `STALE_READING_OVERRIDE`。
- 请求过大：413；资源 ID 不存在：404；数据未就绪：503；未知程序错误：500，响应不泄露堆栈。
- 缺字、读音歧义、体裁待定属于正常分析结果，返回 200。
- 相同输入、数据版本、规则版本、上下文版本、作品版本和用户覆盖必须产生相同业务结果；数组稳定排序，业务响应不混入随机 ID 或时间戳。

### 6. 汇总状态算法（组长实现）

1. 有未被认可救法解决的 `severity=error && status=fail`，汇总 fail，同时保留不确定项。
2. 没有确定硬错误，但必检项 uncertain、解析质量 needs_review、影响结论的模板未确定，汇总 needs_review。
3. 已确认不适用近体规则，汇总 not_applicable；仍返回逐字标注和归部信息，不输出近体硬错误。
4. 形式或关键规则属于尚未支持范围，汇总 unsupported，不能显示通过。
5. 必检项均可确定通过，汇总 pass。非关键位置的读音歧义、三仄尾警告等仍展示，不隐去。

若同时出现“不适用/不支持”和参考检查结果，参考偏离必须是 info/warning，不作为上述第一步的硬错误。

### 7. 语言学口径

- 平水韵、词林正韵采用传统声类：平为 P，上、去、入为 Z。词林正韵来源仅给仄声时保留 ze_unspecified。
- 中华新韵采用普通话本调：一二声 P，三四声 Z；不把语流变调作为默认格律声调。
- 旧入声到新韵按具体字、读音、义项建立联系，不按旧韵部整体转换。
- 选择词林正韵只改变归部，不自动启用词牌，不自动允许近体模板平仄通押。
- P0 支持五绝、七绝、五律、七律；常见孤平自救、特拗、对句相救；其他救法明示待复核。
- 三仄尾默认警告；孤平采用声明过的窄义教学口径；不得将“一三五不论”做成无条件通配。
- 乐府是可与形式标签并存的历史标签。不能“乐府一律免检”，也不能“不合律就是古体”。
- 《静夜思》使用有来源的古绝案例标注；《黄鹤楼》保留七律形式和特殊拗律说明，不能改判古体免检。
