## 1. 你现在怎么用

1. 将配套 `poetry-checker` 启动仓库设为共享项目基线，再把 [组长任务书](10_组长_启动与集成任务书.md) 交给本地 GLM。先读仓库 `README.md` 与 `HANDOFF.md`，复用已有 Schema、fixture、模板和测试，接着完成 API/Web mock 闭环。
2. 将 A–E 各自的任务书分别发送给对应成员。每位成员将自己的完整文件交给 DeepSeek harness，工作目录指向同仓库的本地检出；D 按新版负责业务接入，不自行决定视觉。
3. D1 上午末由你冻结接口，记录版本与提交号；将共享仓库地址、冻结提交和安装命令告知成员。不要让五位成员各自建立一套独立应用。
4. 成员从任务书中的“首个两小时”开始，使用短分支和约定目录。公共骨架暂未就绪时，先写模块纯逻辑、fixture 和测试，不擅自创建另一份公共契约。
5. 每天至少一次主干集成；D3 冻结 P0 功能；D5 下午至少半天联调和彩排。

Claude 试接入后直接发送 [英文设计任务书](17_Claude_Frontend_Design_Brief_EN.md)，已含英文设计说明、视图接口、公共类型和验收；应用界面仍为中文。只有聊天入口也可产出明确文件/补丁，由组长转交本地落盘。接入约 1 小时不可用时交 Codex 候补，D 继续业务工作，不空等。

无需把上一轮长聊天一并发给成员：共八份独立任务书。组长、A–E、Codex 的七份含中文公共契约；Claude 一份为英文，含同源生成的公共类型和英文语义说明。D 另内嵌设计协作约定；Claude 的对应视图类型从同一源生成，避免两份接口漂移。

## 3. 成员可复制的开工消息

```text
附件是你的完整任务书，请阅读全文，包括公共契约附录。
你的工作目录是我给你的共享仓库本地检出，角色和可修改目录以任务书为准。
请先检查现有仓库、AGENTS.md、未提交改动和契约冻结记录，再执行“首个两小时”。
直接完成明确范围内的代码、测试和交接，不只回复计划，不改其他成员模块或公共契约。
依赖未就绪时用任务书约定的 fixture 推进；事实不确定写明待验证，不猜测。
每次返回：完成内容、修改文件、真实执行命令与结果、阻塞、下一步。
```

组长另行提供的真实协作信息只有：仓库地址/本地目录、冻结提交、团队实际日期和安装环境。这些不能在文档中凭空编造，不影响先从本地明确任务开始。

## 4. 四项必须统一的口径

- 平水韵、词林正韵按传统声类；中华新韵按普通话本调，不用语流变调偷换。
- “未知/歧义”“不适用”“尚未支持”“明确违规”分别表达，不能都画成通过或错误。
- 运行时判定依赖数据与规则；不为了合律选音，不因不合律改判古体。
- 任务书中的测试指标是待实现的门槛；没有运行和审核就不能声明已达标。

## 6. 契约修改

独立任务书附录便于单文件分发，不代表每个人可以独立改协议。代码落地后 `packages/contracts` 的组长冻结版本是唯一权威。变化必须带版本和变更记录，同时更新生成类型、OpenAPI、fixture 和测试。
