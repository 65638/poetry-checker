## 边界

## 首个两小时

1. 复跑readings测试并保护现有11条规则，检查真实来源引用及候选仍存在。
2. 从 `tests/golden/cases/` 读取三首已审正文，按三书各自解析/lookup/语境规则处理，形成**9个组合、合计288字位**的矩阵；同一个汉字在不同位置不可合并掉语境。
3. 先交A《登鹳雀楼》词林/新韵缺口，再交其余两首。每位列候选全集、有效候选、排除依据、toneStatus和阻断ID；无依据保留全部候选。
4. 优先定位平仄临界多音与韵脚歧义；新韵“白”可能有多个现代候选，不能根据旧韵结果强选，也不能按常用拼音拍板。

## 与A/GLM的接口

输出 `data/reviews/d3-b-effective-candidates.json`，草案：

```json
{
  "caseId": "golden-dengguanquelou-ps-v1",
  "book": "xinyun",
  "dataVersion": "真实版本",
  "tokens": [{
    "tokenId": "l1c1",
    "character": "白",
    "candidateIds": ["真实候选ID"],
    "effectiveCandidateIds": ["真实候选ID"],
    "contextRuleIds": [],
    "approvedContextEvidenceIds": [],
    "unbackedEffectiveCandidateIds": ["真实候选ID"],
    "toneStatus": "resolved"
  }]
}
```

这是审核产物，无新HTTP端点。正式交付中替换全部示意值；toneStatus按候选推导，不能照示例写死。输出任一有证据、所有候选有证据、所有**有效**候选有证据三列。blocked、unknown、ambiguous分开，不能把多读同调写成读音已确定。

新增语境必须三件套：rules/evidence/sources；使用真实candidateId和固定字位，选择理由来自义项/来源或已批准裁定，不来自模板期望。引用别书裁定时先证明词义可迁移与本书候选归属，不能换book字符串冒充已审核。未确认项放报告队列，不进入approved运行选择器。

## 必须通过的正反例

| ID | 输入/动作 | 预期 |
|---|---|---|
| B01 | 平水三首原版 | 既有11语境不回退，里选上四纸、竞争候选保留 |
| B02 | “里”“千里”“里外”“欲穷千里山” | 固定句规则不泛化；仍按有效候选证据门槛处理 |
| B03 | 同调双读但都已审 | readingStatus=ambiguous，toneStatus可resolved，不瞎选 |
| B04 | 同时有P/Z、缺语境 | 平仄保持不确定，不挑合律读音 |
| B05 | 语境证据缺失、错kind、未审核、候选失效 | 依既有约定忽略/报错，不以rhyme_entry替代语境证据 |
| B06 | 换韵书后提交旧candidateId或旧inputHash | 既有覆盖校验拒绝，不能跨书沿用 |
| B07 | 新韵读旧诗 | 使用普通话本调；不擅自将“一/不”连读变调当格律本调；古入声映射逐候选记录 |
| B08 | 报告与版本变化 | 再生成JSON/Markdown；独立从真实快照验证计数，不用旧报告自证 |

旧韵“入声归仄”，新韵按现代候选本调；同一作品跨书可产生不同结论，不改字、不改义来对齐结果。词林主部与子卷按A的真实结构处理。

