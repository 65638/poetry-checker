## 明确的输入输出

- 输入始终是现有AnalyzeRequest：text/rhymeBook/genreHint/formHint/ruleSet/readingOverrides；输出只消费AnalysisResponse，不在前端重判格律或用标签改诊断等级。
- `onLoadExample(id)` 写入固定正文并按既有机制使旧报告stale、旧覆盖无效；后续提交根据当前请求返回新report。是否能导出由既有report/stale状态决定。
- 特例说明来自API的Finding状态/消息/证据。Codex修复前先记录黄鹤楼已知问题，修复后复验；不要在UI按标题隐藏红字。
- 已有审批只覆盖具体范围，readyz503不能被前端误作所有分析不可用；保留服务端的可执行错误信息，但不要显示密钥、原始堆栈或把用户内容打日志。

| ID | 场景 | 验收结果 |
|---|---|---|
| D01 | 点击三首示例 | 按钮可用；正文与已审版本一致；当前书不被偷偷切换 |
| D02 | 平水登鹳雀楼真实提交 | 展示20字位、版本、合律；非fixture-only；正文/配置/报告同源 |

| D04 | 字位→候选→选音→重查 | 只选真实可用候选；提交override和当前hash；拒绝旧hash/跨书选音；证据可追溯 |

## 单份任务书的开工约定

环境固定 Node 24.19.0 / pnpm 11.25.0。先检查 git status，保护现有改动，再 git fetch origin；使用包含 f42172f 的最新 main 建本书指定的独立分支。不要在别人正在使用的主工作区切分支、reset 或覆盖文件。

新克隆时运行：

```sh
pnpm install --frozen-lockfile
pnpm verify
```

已有依赖时先做本模块相关检查，交付前跑全仓 verify，记录实际 exit 和测试数。根依赖/lockfile/CI改动交GLM，不能自行升级框架。阻塞30分钟交最小复现，超过60分钟请求GLM重新编排，同时继续不依赖该阻塞的工作。

每2小时交一次可运行增量。HANDOFF包含：base/head SHA、变更路径、实际行为、测试命令与结果、依据/版本影响、未完成及下一责任人。开PR后交组长转发摘要；任务书本身不代表已执行，也不授权向成员直接发送消息。
