# 诗格律与韵脚检查器：5 天项目大纲

文档版本：交接方案 v1.3（Claude 拟接视觉/展示组件，D 专注业务工程；Codex 候补）；公共接口基线仍为 v1.0；更新日期：2026-10-16。实现进度以启动仓库的交付记录为准，不将本方案全文视为已完成。

## 1. 项目结论

采用 TypeScript 单仓库、模块化单体、确定性格律引擎和版本化韵书数据。6 人在 5 天内交付一个可离线演示的前后端 Web 应用。按每人每天 6 个有效工时计，共 180 人时，计划约 150 人时，保留 30 人时风险余量。D5 下午至少 3 小时全员联调和彩排，不排新增功能。

代码主要由智能体生成；人负责契约、事实核定、评审和验收。Codex 实现公共契约和格律核心，承担技术复核与疑难修复；GLM 负责本机骨架、API 和集成；Claude 接入后负责视觉/展示组件，Codex 候补；A–E 的 DeepSeek 执行边界清晰的任务，其中 D 负责前端业务工程。运行时判断不依赖大模型。Claude 尚未接入，其可用性待验证。

150 人时仍按六名真人的组织、核验、联调和交付估算，不把 AI 算成第七名成员，也不因增加 Codex 而扩大 P0。C 将核心编码工作转为独立验收、反例、规则依据和封装，保持完整模块责任。

## 2. P0 范围与完成标准

必须全部完成：

1. 用户粘贴诗文，选择平水韵、词林正韵或中华新韵；逐字标注平仄、韵部、读音状态。
2. 支持五言/七言绝句、五言/七言律诗的 16 套基本模板；检查平仄、押韵、粘对、孤平、三平尾、三仄尾和审核过的常见拗救。
3. 对已确认古体显示“不适用近体规则”，保留字音和归部；体式未确定或暂不支持时分别提示。
4. 乐府与形式标签分离，不按“乐府”二字一律免检。
5. 多音字提供候选和依据；不能确定时允许用户选音后重查。
6. 提供可视化逐字谱、诊断定位、证据抽屉、少量审核案例、复制/JSON 导出。
7. 提供契约、自动化测试、人工金标准、数据来源、规则口径、限制说明、启动文档和演示脚本。

明确不进入 P0：动画打磨、词牌格律、语义改诗、完整语义对仗、账号、支付、社区、复杂部署。P1 只在所有 P0 验收通过后启动。前端在 P0 开发时正常保持组件独立、状态清楚和稳定标识，方便后续加入动画。

## 3. 技术选型

| 层 | 选择 | 理由及备选 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 适合组件与 mock 并行；全组明显更熟 Vue 时仅能在 D1 冻结前统一替换 |
| 后端 | Fastify + TypeScript，Node.js LTS | 与前端共享契约；核心算法纯函数；若全组更熟 Python，可在冻结前统一选 FastAPI，不能中途双栈 |
| 契约 | Zod 唯一源，生成类型/OpenAPI | 防止前后端手写类型漂移 |
| 数据 | 来源快照、规范化 JSONL/JSON、SQLite | 可审计、可复现、可离线；驱动阻塞超过 2 小时切只读 JSON 索引 |
| 测试 | Vitest、Playwright、MSW | 分别负责模块、端到端、前端模拟响应 |
| 工程 | pnpm workspace、ESLint、Prettier、CI | 锁定依赖，统一命令，小 PR 集成 |
| 交付 | 本地一键运行；容器化可选 | 首先保证教室环境可启动，容器不阻塞主线 |

## 4. 架构与数据流

```text
浏览器：输入、韵书、体式、人工选音
   ↓ POST /api/v1/analyze
API：请求校验与编排
   ↓
M2 文本解析/位置映射 → M1 批量查字及证据
   ↓
M2 上下文消歧与有效候选
   ↓
M3 整诗模板候选与吻合特征
   ↓
M5 体裁、历史标签、规则适用性
   ↓
M3 逐项格律检查及可解释输出
   ↓
API 汇总版本、证据、状态 → M4 展示与复查

离线数据：来源快照 → 清洗 → 多对多归属 → 校验/抽样 → 发布包
```

禁止循环依赖：M3 不导入 M5，API 调用两个阶段。前端不重写判断。M2 不为了合律选读音。M1 不根据诗句修改韵书。

## 7. 数据工程与音韵口径

### 7.1 已核查的候选来源

以下信息沿用本项目方案阶段 2026-10-16 的联机核查。它不等于字表已逐字验证，也不等于所有上游授权已完成核定。

| 来源 | 已核查内容 | 使用方法 |
|---|---|---|
| [chinese_word_rhyme](https://github.com/charlesix59/chinese_word_rhyme) | 有三套结构化表，仓库标 MIT；提交 `ff0e9c13fb037c43e0eaa5dc929c0fe4fa2ffb18` 的平水韵只有 105 部，缺上声三讲 | 以原韵部表导入，不能用单字单值平仄表；修复需单独补丁 |
| [维基文库平水韻](https://zh.wikisource.org/wiki/平水韻) | 有上声三讲；页面声明 CC BY-SA 4.0 | 冻结修订版本，补缺、对照并保留署名/许可 |
| [维基文库詞林正韻](https://zh.wikisource.org/wiki/詞林正韻) | 可访问；页面声明 CC BY-SA 4.0 | 对照 19 部，保留声类 |
| [pinyin-data](https://github.com/mozillazg/pinyin-data) / [phrase-pinyin-data](https://github.com/mozillazg/phrase-pinyin-data) | 仓库声明 MIT | 现代读音和词组候选，不能直接证明古诗语境读法 |
| [CC-CEDICT](https://cc-cedict.org/wiki/) | 页面声明 CC BY-SA 4.0 | 现代词语读音和义项，保留条目定位 |
| [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) | 仓库声明 MIT | 名篇文本候选；体裁、异文、读音另审 |
| [hantang/rhyme](https://github.com/hantang/rhyme) | README 声明文字整理 CC BY-NC-SA 4.0 | 可作课程对照；不能当无条件可商用数据 |

候选仓库 MIT 不自动覆盖所有转载数据的上游权利。中华新韵具体底本和授权链待验证；D1 必须明确采用哪个版本。无法核实时从确认过的十四韵规则与许可明确的现代读音源重建，并标明重建方法，不能伪称官方原表。

### 7.2 模型与清洗

- 字形 → 多个读音/义项候选 → 多条归部 → 多条证据。古今音关联独立建表，允许缺失和一对多。
- 不知道义项、反切、古今关联时置空或保留候选，不由 AI 补造。
- 快照固定 → 解析 → 区分正文/注文 → 规范化 → 同一归属去重 → 保留跨部重复 → 独立修订 → 生成索引 → 校验/抽样。
- 平水韵名称集合为上平 15、下平 15、上 29、去 30、入 17，共 106；词林 19、新韵 14。不能只校验总数或用空目录凑数。
- 每部至少人工抽 2 条，共 278 条；另抽至少 60 条入声、多归属、简繁与核心用例。A 初审、E 抽检、组长裁决。
- 发布报告列：字形数、归属数、多归属数、缺失、修订、冲突、未审核项，不声称全量无错。

### 7.3 入声、读音与声明

| 字 | 平水韵 | 新韵本调 |
|---|---|---|
| 白 | 入声十一陌，仄 | bái，阳平，平 |
| 一 | 入声四质，仄 | yī，阴平，平 |
| 雪 | 入声九屑，仄 | xuě，上声，仄 |
| 物 | 入声五物，仄 | wù，去声，仄 |

旧入声不按整个韵部统一“转为某声”。新韵按普通话本调；不自动应用“一、不”和三声连读的语流变调。已发现候选新韵表将“一”列在多个声调，须审核，不静默覆盖。

新韵固定说明：“当前按中华新韵及普通话本调检查，古入声字可能改判为平声；本结果不代表该作品在传统韵书下出律。”

消歧优先级：用户选择 → 审核词组/语境规则 → 可解释词表匹配 → 保留歧义。不得用“哪个读音合律”决定读音。现代拼音作为今读参考，不伪装成古音重建。

建立至少 60 个带语境的多音字目标位置，划分开发/留出集，近似诗句不能跨集泄漏。自动判定准确率目标 ≥95%，覆盖率目标 ≥60%，均待实测并报告分母；达不到时收紧自动判定而不是猜测。

## 8. 格律与体裁

### 8.1 基本句式

| 型 | 五言 | 七言 |
|---|---|---|
| A | 仄仄平平仄 | 平平仄仄平平仄 |
| B | 平平仄仄平 | 仄仄平平仄仄平 |
| C | 平平平仄仄 | 仄仄平平平仄仄 |
| D | 仄仄仄平平 | 平平仄仄仄平平 |

整诗选择模板，不逐句拼凑最优句式。可变位置受孤平、尾式和变格约束。

- 粘对以第二字为主要判别点，结合五言二四、七言二四六及整句变格检查；已认可变格不能再机械重复报错。
- 押韵检查所有韵脚的公共韵部；不能仅做相邻两两相交。
- 孤平采用窄义 B 型口径，不是简单“全句只一个平声”。三平尾是错误；三仄尾默认警告。
- P0 支持孤平自救、常见特拗、常见对句相救。未知救法保留偏离并提示复核。
- 首句借邻韵没有审核过的关系表时不自动放行；不伪造邻韵关系。
- 规则集参考王力等资料，具体版本、章节和页码待 D1 核实；严禁虚构引用。

### 8.2 体裁与适用性

形式与历史标签分离；乐府可以与近体形式并存。

1. 用户指定形式优先，结构不符仍提示，不自动换古体。
2. 作品正文精确匹配审核版本，可使用有来源的体裁元数据；不能只凭标题。
3. 四/八句五/七言文本进入近体候选分析。
4. 低吻合度不等于古体；保持待确认并展示参考偏离。
5. 排律等未实现形式为 unsupported，不是 not_applicable。

初始启发式：`0.65×平仄吻合 + 0.20×粘对吻合 + 0.10×押韵一致 + 0.05×可靠对仗辅助`。缺项重新归一化；可判关键位不足 80% 时不做高把握判断。≥0.90 为近体候选，0.75–0.90 待确认，低于 0.75 不自动免检。这些数值是待校准工程阈值，不是概率。

| D5 下午至少半天 | 联调复验、离线测试、两次完整彩排 | 有可运行包、录屏和静态报告备份 |

每天 15 分钟阻塞同步，中段一次集成，结束前一次主线冒烟。首次联调不能留到 D5。

## 11. 金标准与验收

| 作品/用例 | 预期 | 注意 |
|---|---|---|
| 登鹳雀楼 | 平水韵下五绝通过；流/楼下平十一尤；白/一古入声 | 新韵结果不要求完全一致 |
| 静夜思 | 审核版本作为古绝，不强报近体错误 | 不能把所有不合谱五绝都判古体 |
| 黄鹤楼 | 七律形式、特殊拗律说明、偏离可见 | 不判完美常格，不改判古体免检 |
| 木兰诗 | 审核乐府标签和规则不适用性 | 乐府标签本身不是免检条件 |
| 改韵脚、改节奏位 | 可定位真实错误，给出规则和字音依据 | 固定模板隔离测试，不要求只出现一个关联诊断 |
| 多音、缺字、模板并列 | 待确认或信息不足 | 不能显示全绿通过 |

规模目标：12 首审核作品、至少 36 组规则用例、至少 60 个多音字目标位置、至少 12 个系统场景。已人工批准的金标准是确定性回归；开发样本与留出测评分开，不用模型自己造答案自证。

发布门槛：P0 全过；无崩溃、错误绿灯、错误强制选音、证据断链、位置错乱；数据/规则版本固定；所有主线 E2E 通过；文档齐全。普通开发机热启动分析 20–56 字作品的后端 P95 目标 ≤500ms，D4 报告环境和实测样本，不预先声称达标。

## 12. 协作规范

- 短分支，小 PR，当日尽量合并；main 可构建启动。契约由 Codex 实现、组长冻结；共享配置和依赖由 GLM 维护、组长合入。
- 提交：`feat(data): 补上声三讲及来源`、`fix(prosody): 修复公共韵部误判`、`test(readings): 增加歧义用例`。
- PR 写变更、原因、验证命令与结果、契约/数据影响和限制。
- 契约变化同 PR 更新 Schema、类型、OpenAPI、fixture 和测试，不口头约定。
- 成员先看 diff 再提交；不得更改金标准迎合实现。
- 联调顺序：冻结 fixture → 模块测试 → API 真数据 → 前后端 → E2E。
- 上游未完成时用明确标记的 fixture；发布不能接 mock 或演示专用小字表。
- 用 `docs/ownership.md` 记录每个智能体的独占路径；接管时保留现有提交和失败命令，原写入方暂停同路径修改，其余模块继续。

## 13. 风险与降级

| 风险 | 触发 | 动作 | 底线 |
|---|---|---|---|
| 数据缺部/污染 | D1 完整性失败 | 来源核对、独立补丁，A 专注数据，GLM 协助机械导入 | 不用空韵部凑数 |
| 新韵版本/许可未明 | D1 无可追溯来源 | 核定版本或按明确规则重建，记录许可 | 不混入中华通韵，不虚称授权 |
| 入声映射出错 | 古今关联无依据 | 双轨查询、缺关联不推断 | 不按整部迁移 |
| 多音覆盖低 | 留出集误选或覆盖不足 | 收紧规则，提供人工选音 | 不靠合律猜音 |
| 拗救实现滞后 | D2 基础引擎未完成 | Codex 优先修核心，C 提供反例与依据，GLM 处理集成；罕见救法待复核 | 已承诺三类常见变格仍要验收 |
| 体裁误判 | 出律改古体/乐府免检 | 标签分离、人工选择、保留参考检查 | 不用低吻合度免责 |
| 接口漂移 | 联调字段不符 | 单一 Schema、契约测试、组长修订 | 不允许多套权威定义 |
| harness 掉队 | 两轮无可运行产物或阻塞半天 | 提交现状和失败命令，切小任务；算法/疑难交 Codex，机械适配/环境交 GLM | 独占路径交接，未跑测试不得声称成功 |
| Codex 批次尚未就绪 | 核心基线未进入仓库 | C 继续封装、独立样本和依据核查，GLM 继续 API；组长可交接具体子任务 | 不空等整个模块，不同时写 core |
| Claude 未接通/设计迟交 | 试接入约 1 小时不可用，或约 2 工作小时无可检查切片 | Codex 候补；D 用固定视图接口继续业务，必要时按既定视觉规格机械落地 | 不扩大 P0、不等完整设计才接 API |
| 视觉反复推翻/样式冲突 | D1 未收敛或多人改展示目录 | 最多两轮集中方案修改，单写入方，D4 集中视觉走查 | 五种状态/证据语义不为美观让步 |
| SQLite/环境阻塞 | 超过 2 小时 | 切同源 JSON 只读索引 | 证据和版本不能丢 |
| D4 缺陷多 | P0 未验收 | 全员停 P1；先错误结论、再主链路、再显示 | D5 下午不能排满新增开发 |
| 演示失灵 | 网络或机器变化 | 离线包、锁依赖、录屏、静态报告 | 备份不替代可运行交付 |

压缩排期时先删 P1、动画和罕见变格自动识别；不能删除三韵书、歧义表达、来源或测试。最低要求未实现时如实列为未完成，不能重新命名成已完成降级。

### P1 动画实施范围

| 位置 | 效果 | 建议时长 |
|---|---|---|
| 按钮、选项卡 | 悬停/按下反馈，选中背景平滑变化 | 100–150ms |
| 分析结果 | 整块轻微淡入，减少页面位置跳动 | 150–250ms |
| 证据抽屉 | 滑入/淡入与平滑退出 | 200–250ms |
| 点击诊断 | 滚动到对应字，短暂高亮 | 滚动约 200–300ms；不锁定操作 |
| 人工选音复查 | 已变化的平仄、韵部、诊断轻微过渡 | 150–250ms |

优先用 CSS transition/animation；复杂进出场或布局过渡确有需要时再使用 Motion，由组长统一锁定依赖。设计方改展示层、D 接业务，总量仍为 D 组织落实约 2–4 人时、E 约 0.5 人时复验；复杂布局过渡另估半天至一天，不默认纳入基础范围。

动画只影响前端呈现，API 与业务状态照常更新：结果返回即展示，不用固定等待延迟操作；切原文/韵书时取消旧动画，避免旧高亮串到新结果。支持 `prefers-reduced-motion`，减少动态模式下关闭位移与平滑滚动，同时保留文字、焦点和状态反馈。验收含快速连点、连续选音、键盘/焦点、手机布局和减少动态模式；无需为每个动画帧编写测试。
