# 队员 D：前端真实联调与审核状态展示任务书

## 任务目标

把 AI 初审、人工异常复核和证据未就绪状态在正式页面中清楚展示，保证真实 API 未就绪时用户能理解原因；不重新实现格律算法。

## 允许修改范围

`apps/web/`、前端 HANDOFF、前端测试和 UI 文档。不得修改公共契约、API 状态语义或 `packages/` 核心算法。

## 必须交付

1. 真实 API 的 `DATA_NOT_READY`、`ambiguous`、`unknown`、`needs_review` 状态展示；
2. 页面明确显示当前韵书 `dataVersion` 和“开发联调/待人工审核”提示；
3. 点击字位时显示候选、平仄候选、证据 ID 和来源定位；
4. 不把 fixture 结果标成真实名篇结论；
5. 375px 和 1440px 两种布局回归；
6. 支持 `prefers-reduced-motion`，动画不能影响键盘和错误提示；
7. 初始页与结果页的状态切换可复现，不自动弹出无关面板。

## 视觉要求

- 诗句是页面视觉中心；
- 平仄、韵脚、诊断等级和证据状态层级清晰；
- 纸纹、印章和动效服务于阅读，不遮挡结论；
- 错误状态必须比装饰动效优先展示。

## 验收命令

```powershell
pnpm --filter @poetry/web test
pnpm --filter @poetry/web build
pnpm verify
```

浏览器验收使用 `http://localhost:5173/`。如果 `127.0.0.1:5173` 拒绝连接，先确认 Vite 的监听地址，不要把这当成前端业务错误。

## 给 AI 的开场指令

```text
你负责前端审核状态和真实联调展示。先读本任务书、apps/web/HANDOFF-D2.md、docs/reviews/AI初审_人工异常复核方案_2026-10-18.md 和现有 visual-spec。只修改 apps/web。不要重写 API 契约和格律算法。先复现现有页面，再用固定输入补齐 DATA_NOT_READY、ambiguous、unknown、needs_review 的展示和键盘/移动端回归。
```
