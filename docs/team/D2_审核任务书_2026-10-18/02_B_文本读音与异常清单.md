# 队员 B：文本解析、选音与异常清单任务书

## 任务目标

为三首金标准生成 96 个字位的逐字机器初审表，准确标出候选、平仄、证据缺口和多音异常；为需要语境消歧的位置提出可审核的上下文规则。

## 允许修改范围

`packages/readings/`、`data/context/`、`data/reviews/`、B 的 HANDOFF 和读取质量文档。不要修改 `apps/api/`、`packages/prosody/`、韵书原始快照。

## 固定作品

- 《登鹳雀楼》20 字位；
- 《静夜思》20 字位；
- 《黄鹤楼》56 字位。

正文以 `data/works/review-queue.json` 为准，不混入异文。

## 必须交付

1. `data/reviews/golden-token-review-2026-10-18.json`；
2. 同内容 Markdown 表格；
3. 96/96 字位候选覆盖统计；
4. 10 个高优先级多音字异常清单；
5. 上下文规则草案：短语、目标偏移、候选 ID、平仄、证据需求；
6. 说明哪些位置可以确定、哪些必须保持 `ambiguous` 或 `unknown`；
7. 真实快照与旧 `sample-d1` 的版本差异说明。

重点位置：

- “更上一层楼”的“更”；
- “举头望明月”的“望”；
- “低头思故乡”的“思”；
- “乡”、 “乘”、两个“空”、“不”、“汉”等。

## 关键规则

- 不得根据诗句合律与否选择读音；
- 候选证据未审核时，`resolveReadings` 必须继续 fail-closed；
- 上下文规则只有在候选 ID、来源和证据齐全时才能建议为 `approved`；
- 无法判断时明确写 `ambiguous`，不能默认现代普通话读音；
- 使用当前 manifest 的 `pingshui.full-d2-patched.json`，不要用旧七字样本冒充全量结果。

## 验收命令

```powershell
pnpm exec vitest run packages/readings/tests
node node_modules/tsx/dist/cli.mjs packages/readings/scripts/d2-coverage.ts
pnpm verify
```

报告必须包含分母、数据版本、缺字数、多候选数和未审核证据数。

## 给 AI 的开场指令

```text
你负责三首金标准的逐字读音初审。先读本任务书、packages/readings/HANDOFF.md 和 docs/reviews/AI初审_人工异常复核方案_2026-10-18.md。只修改本任务书允许的目录。生成 96 行逐字表和 10 个多音异常清单；不要用格律反推读音，不要把未审核证据改成 approved。先交报告，再处理确定的测试或数据接线问题。
```
