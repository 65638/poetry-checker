# 队员 C / DeepSeek：D4 独立验收与规则依据

## 项目上下文与统一开工规则（本卡可单独投喂）

六人五天课程项目“诗格律检查器”，仓库 https://github.com/65638/poetry-checker。本轮D4统一接收D1–D3遗留；保持已经验收的功能，暂停新的UI/动画。GLM额度不足，由Codex担任集成和技术接管，不等待GLM。

开工读 `AGENTS.md`、`README.md`、`HANDOFF.md`、`docs/ownership.md`，再读本卡指定的最新交接。历史顶部/原PR可能过时，以实际代码与证据SHA为准。Node 24.19.0、pnpm 11.25.0。公共契约、10个ruleId及CheckerViewProps冻结；没有本批明确交接的目录不修改。

基线：完整本地参考为 `feat/claude-distinctive-poetry-ui@4d39037`；编制时还未推送。Codex先发布 `origin/integrate/d4` 并广播实际SHA，不能把旧 `origin/main@05e1acb` 当完整D4代码。你可以立即在现有checkout只读盘点，但写入前需取得D4基线。自己的checkout先 `git status` 保护未提交工作；在干净且独占的checkout：

```sh
git fetch origin --prune
git rev-parse origin/integrate/d4
# 上一命令成功并核对组长广播的SHA后才执行，禁止沿用旧分支整包覆盖：
git switch -c feat/c-d4-closeout origin/integrate/d4
pnpm install --frozen-lockfile
pnpm verify
```

将c换为本卡角色小写；分支已存在先检查，不覆盖；ref未发布则立即报缺少基线SHA，继续只读任务，不自行用main替代。禁止reset/clean、重写他人提交、修改审批原件、历史证据或用当前输出反写金标准。发现新输入时由Codex完成合并，不能自行扩大写入范围。

本地最近独立验证733测试/18浏览器通过；当前API九格3通过6数据阻断，三库全量审核未完成。不能复制历史数字冒充本轮测试。合成fixture只用于明确标识的受控测试；主路径必须真实API。AI初审≠数据approved；新批次需真实接受记录，旧批次不重复问。

## 每批交付格式

独立提交＋草稿PR（目标为已发布integrate/d4）；本角色 `docs/handoffs/d4-c.md` 写实际base/head、改动文件、输入版本/依赖、命令退出码/计数、可定位产物和明确未运行项。首两小时交最小批次；每次出现阻塞30分钟就报，不空等半天。不发消息给其他成员，由组长转发。公共验收表由E单写，公共根配置/CI/API由Codex单写。

提交前运行对应模块检查及 `pnpm verify`；只有新改动、失败或未解问题才追加测试，不重复刷数字。JSON/API/截图证据记录SHA、dirty、时间、模式、版本；失败/阻断/未运行与通过分别记。

## 不重复做的工作与边界

你的D3收尾已验收并集成，见 `docs/handoffs/d3-c-closeout-review-codex.md`。本轮不重写格律引擎、不重新提旧PR整包代码，不修改A/B数据来迎合规则。

只写 `packages/prosody/tests/acceptance/**`、`packages/prosody/src/index.ts`、`packages/prosody/src/adapters/**`、`packages/prosody/src/report/**`、`rules/cards/**`、`docs/rules/**`（新增文档目录可用）、`docs/handoffs/d4-c.md`。core/exception实现由Codex修；API测试由Codex单写。发现缺陷交最小反例＋真实依据，C的预期独立于实现输出。

先读现有10张发布卡、`rules/cards/runtime-review-status.json`、`rules/exceptions/reviewed-works-v1.json`、既有C01–C16和D2矩阵、13/14号裁定原件。

## 必验反例

| 场景 | 预期 |
|---|---|
| 登鹳雀楼平水 | 五绝，通过；真实报告证据闭合 |

| 押韵集合两两相交但全局不交 | 不能误判押韵通过 |
| 普通规则卡ID/版本/来源不一致 | 测试报错，不能把期望改成现有错误 |
