# 队员 A / DeepSeek：D4 三库候选与数据收口

## 项目上下文与统一开工规则（本卡可单独投喂）

六人五天课程项目“诗格律检查器”，仓库 https://github.com/65638/poetry-checker。本轮D4统一接收D1–D3遗留；保持已经验收的功能，暂停新的UI/动画。GLM额度不足，由Codex担任集成和技术接管，不等待GLM。

开工读 `AGENTS.md`、`README.md`、`HANDOFF.md`、`docs/ownership.md`，再读本卡指定的最新交接。历史顶部/原PR可能过时，以实际代码与证据SHA为准。Node 24.19.0、pnpm 11.25.0。公共契约、10个ruleId及CheckerViewProps冻结；没有本批明确交接的目录不修改。

基线：完整本地参考为 `feat/claude-distinctive-poetry-ui@4d39037`；编制时还未推送。Codex先发布 `origin/integrate/d4` 并广播实际SHA，不能把旧 `origin/main@05e1acb` 当完整D4代码。你可以立即在现有checkout只读盘点，但写入前需取得D4基线。自己的checkout先 `git status` 保护未提交工作；在干净且独占的checkout：

```sh
git fetch origin --prune
git rev-parse origin/integrate/d4
# 上一命令成功并核对组长广播的SHA后才执行，禁止沿用旧分支整包覆盖：
git switch -c feat/a-d4-closeout origin/integrate/d4
pnpm install --frozen-lockfile
pnpm verify
```

将a换为本卡角色小写；分支已存在先检查，不覆盖；ref未发布则立即报缺少基线SHA，继续只读任务，不自行用main替代。禁止reset/clean、重写他人提交、修改审批原件、历史证据或用当前输出反写金标准。发现新输入时由Codex完成合并，不能自行扩大写入范围。

本地最近独立验证733测试/18浏览器通过；当前API九格3通过6数据阻断，三库全量审核未完成。不能复制历史数字冒充本轮测试。合成fixture只用于明确标识的受控测试；主路径必须真实API。AI初审≠数据approved；新批次需真实接受记录，旧批次不重复问。

## 每批交付格式

独立提交＋草稿PR（目标为已发布integrate/d4）；本角色 `docs/handoffs/d4-a.md` 写实际base/head、改动文件、输入版本/依赖、命令退出码/计数、可定位产物和明确未运行项。首两小时交最小批次；每次出现阻塞30分钟就报，不空等半天。不发消息给其他成员，由组长转发。公共验收表由E单写，公共根配置/CI/API由Codex单写。

提交前运行对应模块检查及 `pnpm verify`；只有新改动、失败或未解问题才追加测试，不重复刷数字。JSON/API/截图证据记录SHA、dirty、时间、模式、版本；失败/阻断/未运行与通过分别记。

## 交给B/组长的文件接口

这是审核交换文件，不改变公开API；沿用现有候选ID及 `positions` 数组。每个批次一个JSON，另有简短Markdown摘要，路径 `data/reviews/d4/a/<batchId>.json`。最少结构：

```json
{
  "schemaVersion": "d4-review-batch-v1",
  "batchId": "d4-a-实际批号",
  "baseSha": "实际提交",
  "dataVersions": {},
  "approvalRecord": null,
  "entries": [{
    "book": "cilin", "candidateId": "来自快照的真实ID",
    "positions": ["dengguanquelou/l1c1"],
    "evidenceIds": [], "sourceId": "真实来源ID",
    "sourcePath": "仓库内原始文件", "sourceSha256": "原始字节摘要",
    "locator": "可回查定位", "machineStatus": "machine_checked",
    "exceptionIds": []
  }],
  "excludedScope": ["未列举候选", "所属整部", "全库发布"]
}
```

上面是结构示意，空数组与占位不能作为交付记录。文件最终SHA写旁置 `.sha256`，不把文件自身摘要嵌回文件造成循环。无法确认条目标 `needs_review` 并列依据缺口，不先填machine_checked。

B返回语境依赖和有效候选差集；归部依据由你负责，语境选择由B负责。新确认后按现有候选级证据方式落库，并向Codex交新旧版本、ID差异/迁移、影响作品和精确批准记录路径。

## 验收用例与命令

| 用例 | 必须得到的结果 |
|---|---|
| 已批平水范围 | 无新增确认时仍83候选＋三讲；六部误批不复活 |

| 审批扩散反例 | 批准某候选不能使同韵部其他字自动approved；删竞争候选不能解除证据门槛 |
| 新批次重建 | 同源同规则两次业务内容摘要一致；有内容变更必须升版本 |
| 来源缺字/异体 | 如实缺口或有依据补丁，不简繁强并、不虚构反切 |
