## 3. 页面结构

以下是你需要接线和验收的产品结构。布局、字体、配色、响应式展示由设计方按附录实现；本节不要求你另写平行 UI。

### 输入区

- 多行正文输入，清晰提示“只粘贴正文，按标点或换行分句”。
- 三韵书选择：平水韵、词林正韵、中华新韵。
- 体式：自动、五绝、七绝、五律、七律；另可明确选择古体模式。选择古体时清除具体近体 form，避免矛盾请求。
- 示例入口：登鹳雀楼、静夜思、黄鹤楼，正文版本来自审核案例。
- 分析按钮、字符上限说明、输入校验信息。标题与正文不自动混入一个检测字符串。

### 结果区

- 摘要：当前韵书、口径、体式判断、规则/数据版本、结论状态。
- 逐字谱：汉字、P/Z 对应中文“平/仄”、未知/歧义标记；韵脚下划线或框线。
- 原文顺序和标点保留，点击诊断高亮有关 token；根据 API 的 UTF-16 范围定位，不按 DOM 字符索引猜。
- 押韵区展示各韵脚、候选韵部、共同归部状态。
- 粘对区展示关系两端和状态；线条可简化为明确的对应行/字标记，避免耗时动画。
- 诊断按平仄、押韵、粘对、孤平/尾式、变格等分组，支持只看需处理项。

### 证据抽屉

- 当前字、候选读音、传统声类、今读参考、韵部。
- 选择方法：唯一候选、审核规则、用户指定、未确定。
- 规则卡：适用范围、实际与期望、例外说明。
- 来源：名称、版本、条目/页码/JSON 路径、外部链接或本地报告定位。
- 反切缺失时不展示虚构内容；可写“该数据未提供反切”。
- 候选选择按钮，提交该 tokenId/readingId 与上次 inputHash 后重新分析。

## 4. 文案与交互底线

状态必须文字+图形，不仅靠红绿颜色：

| 状态 | 建议文案 |
|---|---|
| pass | 在当前韵书与已实现规则范围内，必检项通过 |
| fail | 检出明确违反当前规则的项目，查看字位和依据 |
| needs_review | 部分读音或体式尚未确定，请查看候选与依据 |
| not_applicable | 该作品不适用本次近体规则，仍可查看逐字音韵信息 |
| unsupported | 当前版本尚不支持此形式/关键规则，不能据此判定合律 |

新韵固定说明：按中华新韵及普通话本调，古入声字可能改判为平；不代表旧韵下出律。词林正韵说明：当前支持该韵书归部，不等于词牌检查已实现。

读音歧义不能显示成“可平可仄所以通过”。多个候选全同平仄时，可显示“平仄已定、读音待定”。用户选音显示“用户指定”，不伪装为系统自动判断。

已认可拗救显示原偏离、救位和规则；不能只删除红字让用户不知道为什么通过。

## 5. API 状态与并发

- 只调用附录 HTTP；不创建另一个请求/响应协议。
- 组件使用生成类型，集中 API client；基础 URL 使用配置，开发通过代理访问。
- 新提交取消旧请求或用请求序号忽略旧响应。快速切韵书、修改正文不显示旧结果。
- 正文变化后使旧选音覆盖失效，清除或提示重新选择；不能套用旧 inputHash。
- 换韵书时清除旧韵书 readingId，重新查询；不复用选音候选。
- HTTP 错误保留输入并显示可恢复提示；分析产生 unknown 是正常报告，不当作网络失败。
- 不能用缓存结果掩盖新请求失败。可以保留旧报告，但必须明显标注它不对应当前输入。
- 原文按文本安全渲染，不使用未消毒的 HTML 拼接。

为后续动画保留清晰结构：逐字谱、诊断列表、抽屉为独立组件；同一原文复查复用稳定的 token/规则标识，原文或韵书变化时按报告身份重置旧高亮。loading 与业务结果状态独立管理，更新时尽量保留布局和用户滚动位置。这些是正常组件设计，P0 阶段无需引入动画依赖。

## 6. 导出与可用性

- P0 支持复制可读摘要与下载完整 JSON。
- JSON 包含原文、请求参数、AnalysisResponse、版本、用户覆盖、所有不确定项；导出不得重新做判定。
- 原文和报告不上传到第三方服务；本地历史属于 P1，P0 不需要持久化用户内容。
- 375px 宽度及桌面布局均可读；七言逐字谱不得被裁掉关键信息。
- 提交、焦点字、抽屉打开/关闭、候选选择可用键盘完成；关闭抽屉返回触发元素焦点。
- 使用明确标签、可读对比度与 loading 文案，不依赖复杂动效。

### 启动条件与工时

### 具体效果

| 编号 | 位置 | 实现范围 | 时长建议 |
|---|---|---|---|
| AN01 | 按钮/选项卡 | hover、按下、选中背景变化；键盘焦点立即可见 | 100–150ms |
| AN02 | 分析结果 | 整块轻微淡入，保持阅读位置；不逐字打字机展示 | 150–250ms |
| AN03 | 证据抽屉 | 轻微滑入/淡入，平滑退出；焦点行为与 P0 一致 | 200–250ms |
| AN04 | 点击诊断 | 平滑定位当前报告字位，短暂高亮；用户可立即继续操作 | 滚动约 200–300ms |
| AN05 | 人工选音复查 | 最新结果立即生效，对变化的平仄/韵部/诊断轻微过渡 | 150–250ms |

### 实现约束

- 先使用 CSS transition/animation，优先 opacity、transform 和局部颜色变化；显式列属性，避免给整页 `transition: all`。
- 动画时长、缓动统一放在样式变量或前端配置中。复杂进出场、列表布局变化确有必要时再引入 Motion；依赖由组长统一锁定，不同时引入多套动画库。
- API 返回就更新最新业务状态，不使用固定 setTimeout 等待动画后才显示结果，不人为拉长 loading。
- 连续提交、切书、选音应能打断旧过渡；旧抽屉或旧报告的字位不能在新结果上继续高亮。不得只凭相同 tokenId 跨不同原文复用动画状态。
- 关闭抽屉后焦点按既有规则返回；退出中的隐藏元素不可继续被键盘聚焦或点击。
- 支持 `prefers-reduced-motion: reduce`：关闭位移、弹跳和非必要动画；诊断定位改为即时滚动，保留文字、焦点和状态提示。JS 触发的滚动也要检查该偏好。
- 避免大面积弹跳、逐字延迟出现、长时间自动滚动。手机端不因动效导致水平溢出或明显布局跳动。
- 只在前端展示层实现，报告、证据、导出内容与 API 契约按原有版本工作。

```ts
  onSelectFinding: (findingId: string) => void;
```

展示入口：`export function CheckerView(props: CheckerViewProps)`。D 的容器持有业务状态；设计方按 props 渲染并触发事件。输入控件可以暂存输入法组合等局部 UI 状态，但不得另存一套分析结果或发请求。

- 业务状态传入后立即展示；动画不能延迟回调或冻结请求。错误文案来自明确错误对象，不能把 unknown 显示为网络故障。

### 2. 术语、索引和状态

- `P` 表示平，`Z` 表示仄；未知不是第三种实际声调。
- `line`、`column` 从 1 开始，按诗句和汉字计数；`startUtf16/endUtf16` 是原始字符串中的半开区间。
- `tokenId` 为 `l{line}c{column}`，例如 `l4c1`。标点不占格律字位。
- `inputHash` 为原始输入 UTF-8 文本的 SHA-256 小写十六进制值。人工选音仅对该原文有效。
- 简繁和异体对应只生成候选，不覆盖原文；不得把“发”无条件合并到“發”或“髮”。
- `resolved/ambiguous/unknown` 分别表示读音确定、有多个合理候选、没有可用候选。
- 规则状态为 `pass/fail/uncertain/not_applicable/unsupported`。
- `not_applicable` 表示规则不适用；`unsupported` 表示形式或规则尚未实现；不得混用。
- `error/warning/info` 是问题等级，与规则状态独立。三仄尾默认 warning；其出现不自动使全篇 fail。
- 判定为 pass 不等于文学评价优秀，也不保证未实现的规则通过。

补充约定：

1. `expectedTones[句序号-1][字序号-1]` 是允许平仄数组；它只是基础模板，不能替代孤平、尾式、变格约束。
2. `possibleTones` 由有效候选计算。任一有效候选声调未知时，`toneStatus` 为 unknown，不能用其他已知候选掩盖它；所有有效候选同为平或同为仄时，平仄可确定而读音仍可 ambiguous。
3. `ze_unspecified` 用于来源只提供“仄声”、不能进一步区分上去的记录，不补造细分类。
4. `neutral` 没有可靠本调时 `tone=null`；不得默认归平。
5. `ContextRule.targetOffset` 按短语 Unicode 码点从 0 计数；每条规则所有短语的目标偏移必须一致，否则拆成多条。
6. 上下文规则若同时选中多个相互冲突候选，不自动任选；退回 ambiguous 并记录冲突。
7. 来源和规则 ID 是稳定标识；报告中引用的每个 ID 必须能在 provenance 或相应查询接口中解析。
8. unverified 的证据只能出现在待核查材料中，不得支撑确定的发布结论。
9. 作品指纹按去除约定的标点与空白后、保留原字形和字序的正文计算 SHA-256。简繁及异文各自登记审核指纹，不自动互认。该指纹不同于原文 inputHash。

### 4. 模块接口

```ts
// M1 / A：异步 I/O 适配器
lookupCharacters(input: {
  characters: string[]; rhymeBook: BookId; dataVersion: string;
}): Promise<LookupResult>

// M2 / B：纯计算。规则和证据由 API 装载后注入。
parseText(input: { text: string }): ParsedPoem
resolveReadings(input: {
  poem: ParsedPoem;
  lookup: LookupResult;
  overrides: ReadingOverride[];
  contextRules: ContextRule[];
}): AnnotatedPoem

// M3 / C：先产出特征，供体裁模块消费；不要导入 M5。
matchTemplates(input: {
  poem: AnnotatedPoem; formHint: 'auto' | FormId; ruleSet: 'teaching-v1';
}): TemplateCandidate[]

evaluateProsody(input: {
  poem: AnnotatedPoem;
  candidates: TemplateCandidate[];
  selectedTemplateId: string | null;
  applicability: GenreDecision['applicability'];
  ruleSet: 'teaching-v1';
}): ProsodyReport

// M5 / E：不用标题独立认定作品，也不修改读音。
classifyGenre(input: {
  poem: AnnotatedPoem;
  candidates: TemplateCandidate[];
  metadata: WorkMetadata[];
  genreHint: AnalyzeRequest['genreHint'];
  formHint: AnalyzeRequest['formHint'];
}): GenreDecision
```

API 由组长依次调用：请求校验 → parseText → M1 查询 → resolveReadings → matchTemplates → classifyGenre → evaluateProsody → 证据汇总 → 汇总结论。

不得形成 `prosody → genre → prosody` 的运行时依赖。两个步骤都由 API 调度。

分析请求示例：

```json
{
```

人工覆盖是在上一次响应的原文、候选和 inputHash 基础上，将 `readingOverrides` 填为 `[{"tokenId":"l4c1","readingId":"实际候选ID"}]`。不能凭空提供读音。

```json
{
  "id": "finding-l1c2-meter",

  "ruleVersion": "1",

  "observed": ["P"],
```

约束与错误：

- 请求不超过 2,000 个 Unicode 码点、100 个诗句；限额在后端执行。
- 没有汉字、枚举非法、指定 ancient 同时强选近体 form、覆盖读音无效：422。
- 有覆盖时 inputHash 必填并与当前原文一致；冲突为 422 `STALE_READING_OVERRIDE`。
- 请求过大：413；资源 ID 不存在：404；数据未就绪：503；未知程序错误：500，响应不泄露堆栈。
- 缺字、读音歧义、体裁待定属于正常分析结果，返回 200。
- 相同输入、数据版本、规则版本、上下文版本、作品版本和用户覆盖必须产生相同业务结果；数组稳定排序，业务响应不混入随机 ID 或时间戳。

### 6. 汇总状态算法（组长实现）

1. 有未被认可救法解决的 `severity=error && status=fail`，汇总 fail，同时保留不确定项。
2. 没有确定硬错误，但必检项 uncertain、解析质量 needs_review、影响结论的模板未确定，汇总 needs_review。
3. 已确认不适用近体规则，汇总 not_applicable；仍返回逐字标注和归部信息，不输出近体硬错误。
4. 形式或关键规则属于尚未支持范围，汇总 unsupported，不能显示通过。
5. 必检项均可确定通过，汇总 pass。非关键位置的读音歧义、三仄尾警告等仍展示，不隐去。

若同时出现“不适用/不支持”和参考检查结果，参考偏离必须是 info/warning，不作为上述第一步的硬错误。

### 7. 语言学口径

- 平水韵、词林正韵采用传统声类：平为 P，上、去、入为 Z。词林正韵来源仅给仄声时保留 ze_unspecified。
- 中华新韵采用普通话本调：一二声 P，三四声 Z；不把语流变调作为默认格律声调。
- 旧入声到新韵按具体字、读音、义项建立联系，不按旧韵部整体转换。
- 选择词林正韵只改变归部，不自动启用词牌，不自动允许近体模板平仄通押。
- P0 支持五绝、七绝、五律、七律；常见孤平自救、特拗、对句相救；其他救法明示待复核。
- 三仄尾默认警告；孤平采用声明过的窄义教学口径；不得将“一三五不论”做成无条件通配。
- 乐府是可与形式标签并存的历史标签。不能“乐府一律免检”，也不能“不合律就是古体”。
- 《静夜思》使用有来源的古绝案例标注；《黄鹤楼》保留七律形式和特殊拗律说明，不能改判古体免检。
