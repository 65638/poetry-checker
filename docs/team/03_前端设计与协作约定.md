## 3. 固定的视图接口

以下是前端内部接口草案；D 在 D1 首个工作小时落为 `apps/web/src/view-contract.ts` 并冻结，设计方只导入。它复用 HTTP 类型，不新增后端字段、不重复定义 AnalysisResponse。下列代码是文档约定，目前尚未生成对应应用源码。

```ts
import type {
  AnalyzeRequest, AnalysisResponse, ReadingOverride,
} from '@poetry/contracts';

export type InputDraft = Pick<
  AnalyzeRequest, 'text' | 'rhymeBook' | 'genreHint' | 'formHint'
>;

export interface CheckerViewProps {
  draft: InputDraft;
  report: AnalysisResponse | null;
  busy: boolean;
  stale: boolean; // 当前展示报告是否已不对应当前输入
  error: { code: string; message: string } | null;
  feedback: string | null; // 复制成功等非判定反馈
  selectedTokenId: string | null;
  selectedFindingId: string | null;
  examples: Array<{ id: string; title: string; text: string }>;
  onDraftChange: (next: InputDraft) => void;
  onAnalyze: () => void;
  onLoadExample: (exampleId: string) => void;
  onSelectToken: (tokenId: string) => void;
  onSelectFinding: (findingId: string) => void;
  onChooseReading: (override: ReadingOverride) => void;
  onCloseEvidence: () => void;
  onCopySummary: () => void;
  onDownloadReport: () => void;
}
```

展示入口：`export function CheckerView(props: CheckerViewProps)`。D 的容器持有业务状态；设计方按 props 渲染并触发事件。输入控件可以暂存输入法组合等局部 UI 状态，但不得另存一套分析结果或发请求。

- `onChooseReading` 只提交当前候选 ID；inputHash、覆盖合并、发请求、摘要失效由 D 处理。stale/busy 时禁用旧报告选音并解释原因。
- `onDraftChange` 只表达意图；D 统一处理古体/具体形式互斥、换书清候选和正文修改。展示组件不得自行推断声调或体裁。
- `selectedTokenId` 打开证据；`selectedFindingId` 驱动当前报告的关联定位。展示组件处理 DOM 焦点、抽屉焦点限制/恢复和滚动；D 负责换正文/韵书/报告时清除旧选择。
- 从 report 读取 summary、checks、relations、provenance；允许按 ID 查找及排版分组，不计算新的合律分、等级或规则结果。
- 业务状态传入后立即展示；动画不能延迟回调或冻结请求。错误文案来自明确错误对象，不能把 unknown 显示为网络故障。

## 4. 默认视觉基线：诗文校读台

用于首轮实现的具体方向：纸白背景、墨色正文、少量青绿与朱红提示，横排、重阅读、轻装饰。视觉优先级为诗文 > 结论与韵书口径 > 诊断与证据。用户未给品牌时先用“诗格律检查器”，不额外设计首页或营销口号。

### 设计变量

| 项目 | 基线值/规则 |
|---|---|
| 页面/面板 | 背景 #F7F5EF；内容面 #FFFFFF；分隔线 #DDD8CC |
| 文字 | 正文 #262923；次要说明 #666A61；实际组合需检查对比度 |
| 主操作与通过 | 青绿 #245C4B；通过还须“通过”文字/图标，不只有颜色 |
| 明确违规 | 朱红 #A52F2F；轻背景 #FFF1EF；定位对应字与规则 |
| 待复核 | 赭色 #805500；轻背景 #FFF6DE；提供下一步动作 |
| 不适用/未支持 | 中性浅底，但标签、说明和图标不同；不与通过共用绿灯 |
| 焦点 | 2px 清晰外框，外偏移 2px；不能被阴影/选中框吞没 |
| 间距/圆角 | 4/8/12/16/24/32/48px；常规圆角 8px，面板不超过 12px |
| 字号 | 操作/正文 16px，辅助信息 14px；桌面诗字 28px，手机 24px；长证据行高约 1.7 |
| 字体 | 操作用系统无衬线；诗文用系统宋/明体优先并提供系统回退。P0 不依赖联网字体，补充平面汉字保留回退 |

这些是可开工的默认值，不宣称已完成视觉验证。设计方可以在 D1 对首版有限修正并集中更新 tokens，禁止每个组件自行选另一套配色。P0 先做一套浅色主题。

### 页面与响应式

- 桌面 1440px：主体最大宽 1200px、居中、页边距 24–32px；输入栏约 340px，报告占余宽，中间 24px。页头紧凑，进入即可粘贴/选韵书。报告顶层放结论、口径及“复制/导出”，随后逐字谱与诊断。
- 768–1099px：上下单列；输入可收起但当前韵书与编辑入口保留；证据抽屉宽度不超过视口减 32px。
- 375px：页边距 16px；七言字位每格至少 44px，字位间隔约 4px可在 343px 内排开；标点单独留行内尾部空间或折入行尾，不挤占可点击字位。若超出，调整网格而不缩到无法点击。证据使用全宽面板，可关闭、可滚动，背景不抢焦点。
- 逐字谱展示汉字、中文平/仄/未定、韵脚标记。注释和文献放证据层，正文不堆满技术字段。版本信息可折叠，但新韵口径必须直接可见。
- 明确分组与留白，不把每个字段变成独立浮动卡片；无大型题图、粒子、玻璃特效或逐字入场。真实功能信息优先。

## 5. 设计交付与验收

首批需要实际 React 展示组件与可运行的开发预览；仅有“典雅国风”描述或一张效果图不算完成。预览用现有合法 fixture，明确开发模式；案例按钮使用审核文本，合成报告不能挂名《登鹳雀楼》。新增 fixture 由 D 构造并经 Schema 校验。

| 编号 | 场景 | 设计与功能都要满足 |
|---|---|---|
| UI01 | 空页面/输入 | 一眼找到正文、韵书、分析按钮，无大块装饰挤走操作 |
| UI02 | 五种报告结论 | 标签与说明可区分；通过也显示口径，待复核有下一步，不适用/未支持仍可读字音 |
| UI03 | 明确违规/诊断点击 | 看到具体字、应该怎样、实际怎样、依据；关联位置不只靠颜色 |
| UI04 | 多音字抽屉 | 候选、选择依据、来源可读；长文献不挤出选音/关闭按钮 |
| UI05 | loading/422/503/陈旧报告 | 保留输入，反馈准确；旧结果明确标记，操作不会误用旧选音 |
| UI06 | 1440/768/375px | 无主要信息裁切；七言可点、长韵部和证据可换行 |
| UI07 | 键盘/可访问性 | 正文普通文字对比度目标 4.5:1、大字和必要 UI 边界目标 3:1；焦点可见、抽屉可退出并恢复焦点 |
| UI08 | 选音/切书/导出 | 设计层回调完整；最终结果与导出不被展示层改写 |

设计方提交开发预览入口、1440/375px 的真实截图与尺寸说明、UI01–UI08 结果及待修问题；E 检查 768px/键盘等边界，D 验证回调与业务。若工具不能启动/截图，明确未执行并交可运行代码，由 D 启动复验，不虚构截图或通过结论。只为有行为风险的交互补测试，不要求逐像素快照。

## 7. P1 动画

全部 P0 通过后再开始。设计方定义并实现展示层过渡，D 接入并处理取消/状态/焦点关联，E 回归。总量维持原基础范围：D 负责组织落实约 2–4 人时，E 约 0.5 人时；不因多一位 AI 再叠加同等预算。

按钮反馈 100–150ms、结果淡入 150–250ms、抽屉 200–250ms、诊断定位约 200–300ms；优先 CSS，尊重减少动态偏好。API 返回立即更新结果，旧动画可打断，不以过渡延迟新结论。无剩余时间则顺延主线交付后。
