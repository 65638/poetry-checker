## 3. 本机网络环境（影响取证方式，必须记录）

- `github.com` / `raw.githubusercontent.com` / `api.github.com`：TLS 叶子证书校验失败（`UNABLE_TO_VERIFY_LEAF_SIGNATURE`），schannel 侧报 `SEC_E_NO_CREDENTIALS`。判定为传输链被中间人替换。
- `registry.npmjs.org`、`cdn.jsdelivr.net`、`unpkg.com`：证书链正常，可正常校验。
- 维基媒体站点：连接超时。
- 于是静态文件统一走 jsdelivr 取**同一固定 ref**，并用“提交/标签双侧摘要一致”来约束内容；未使用 `--no-verify` 之类放弃校验的手段抓取。

**GitHub 私有仓库的克隆/推送在本机同样不可用**（无凭据、TLS 被替换），所以 D1 的分支无法推送，见 `HANDOFF.md`。
